# Analysis Layer · 业务分析(Skills)

> 上级文档:[architecture.md](../architecture.md) · 对应 requirements §4 / §14.7 / §14.8

## 1. 职责

把领域模型 + Tool 能力组合成有业务语义的"分析单元"——每个分析器都是一个 Skill,输出统一 Artifact。

## 2. Skill 清单

| Skill | 职责 | 主要输入 | 主要输出 |
|---|---|---|---|
| **板块中心** | 板块查询、成员、涨跌、资金、估值、热度 | `sector_id` | 板块画像 Artifact |
| **龙头识别器** | 五维评分;按 `sector_canonical.profile` 加载四套权重模板(cycle/tech/consumer/financial) | `sector_id` | 前三龙头 + 评分拆解 + 风险,写入 `leader_score` |
| **热点分析器** | 当日聚焦、持续性判断(一日游/轮动/主线)、传导路径 | 当日行情 + 资金 + 情绪 | 热点 Artifact |
| **大盘分析器** | 指数 + 宽度 + 资金 + 情绪 | 当日行情 | 大盘画像 Artifact |
| **产业链分析器** | 以龙头为中心展开上下游、竞品、原材料、客户、关键事件 | `stock_id` 或 `sector_id` | 产业链图 Artifact |
| **跨市场影响引擎** | 美股 / 商品 / 利率 → A 股传导 | `event_id` 或外部市场变动 | 影响路径 + 受益/承压清单 |
| **事件解释器** | 抽取分工:结构化数字走规则 Tool;公告/新闻文本走 `extract_filing` Tool 落 `inferred` evidence;高价值产业链边由人工录入并标 `fact` | 公告/新闻 raw | 事件 Artifact + Evidence 写入 |
| **长期价值评估** | 基本面 + 估值分位 + 治理风险 | `stock_id` | 长期价值 Artifact |
| **LLM 报告生成** | 综合上述产物输出板块/个股/事件研究报告 | 多个 `run_id` | 报告 Artifact |

## 3. 龙头识别器:权重模板

按 `sector_canonical.profile` 加载不同权重模板。第一阶段四套初值如下,五维合计 100%;数值为可解释的初始点,**M1-T0 数据源 Spike 完成后由 §7 演进路线第二阶段的事件窗口回测重新校准**。`weight_template_version` 写入 `leader_score` 行,版本变更后历史快照保留可审计。

| profile | 规模地位 | 盈利质量 | 成长性 | 市场关注度 | 产业链地位 | 设计意图 |
|---|---|---|---|---|---|---|
| `default`(未分型) | 25% | 25% | 20% | 15% | 15% | requirements §4.2 默认权重 |
| `cycle`(周期) | 30% | 25% | 10% | 10% | 25% | 偏成本曲线、资源量、链上位置;成长性低权重避免周期顶部误判 |
| `tech`(科技) | 15% | 20% | 30% | 15% | 20% | 偏成长性 + 链上位置(产能/订单/客户绑定);研发投入暂用净利润含金量代理 |
| `consumer`(消费) | 25% | 30% | 15% | 15% | 15% | 偏盈利质量(品牌强度通过 ROE / 毛利率代理) |
| `financial`(金融) | 30% | 35% | 10% | 10% | 15% | 偏盈利质量(资产质量、不良率)与规模地位(资本充足) |

### 3.1 第一阶段评分落地规则

第一阶段先保证评分可复现,不追求字段完美覆盖。龙头识别器必须输出 `metric_coverage` 与缺失字段列表。

| 维度 | 第一阶段可用字段 | 降级规则 |
|---|---|---|
| 规模地位 | 市值、营收、净利润 | 市场份额 / 产能缺失时不参与该维度 |
| 盈利质量 | ROE、毛利率、净利率、经营现金流 / 净利润 | 现金流字段缺失时标记风险 |
| 成长性 | 营收同比、利润同比 | 订单 / 产能只有在有 evidence 时参与 |
| 市场关注度 | 成交额、换手率、成交额分位 | 机构持仓 / 分析师覆盖缺失时不参与 |
| 产业链地位 | 手工 fact 边数量、边强度、边置信度 | 无图谱边时该维度为 `null` |

计算约束:

- 同板块内分位数归一化,极端值按 5% / 95% 分位截尾。
- 维度内缺字段时在可用字段之间重加权。
- 某维度全缺失时综合分在其余可用维度间重加权,并降低结论置信度。
- 候选股票至少需要 3 个维度可用,否则只返回"数据不足",不进入前三龙头结论。
- 每个子分数引用指标快照或 evidence;缺 evidence 的子分数不得用于高置信度结论。

**第一阶段产业链地位维度的现实**:由 requirements §12.2 仅维护 5 条美股 → A 股关键映射,绝大多数板块没有人工 fact 边,该维度对它们而言为 `null` 触发"维度内重加权"。第一阶段大部分板块龙头评分实质是 4 维而非 5 维,综合分置信度自动降低并在前端打"产业链覆盖不足"标签。第二阶段将通过 LLM 抽取扩充图谱 / 人工录入更多 fact 边来补齐;在此之前**不**用券商研报标记或行业排名硬填该维度,避免引入未经审计的代理。

## 4. 抽取分工(对应 requirements §14.7)

```
结构化数字(财报数据、行情、资金流)
   → 规则 Tool 直接落 fact / statistical edge

公告/新闻文本
   → LLMGateway.extract_filing
   → 落 inferred evidence + inferred edge
   → 等待规则或人工 review 提升

高价值产业链边(§12.2 跨市场关键传导)
   → 人工录入,标 fact,挂 manual evidence
```

## 5. Artifact 输出契约

每个 Skill 必须产出符合 [architecture.md §5](../architecture.md#5-统一产物契约-artifact-schema) 的 Artifact,关键字段:

- `summary`:一句话结论(提醒服务读取)。
- `highlights[]`:亮点条目(主页/提醒卡片读取)。
- `conclusions[]`:结构化结论,带 `relation_class` + `confidence` + `evidence[]`(经 Conclusion Sink 落图谱)。
- `data`:评分拆解、指标快照、明细(看板读取)。
- `charts[]`:图表配置(前端 ECharts / Cytoscape 直接渲染)。
- `references[]`:依赖的其他 `run_id`(支持组合分析)。

## 6. Skill 之间的依赖

Skill 可以调用其他 Skill(通过 `RunRequest`),形成有向无环依赖:

```
LLM 报告生成
  ├─ 板块中心
  ├─ 龙头识别器
  │    └─ 板块中心
  ├─ 产业链分析器
  └─ 长期价值评估

跨市场影响引擎
  └─ 事件解释器
```

子 Run 的 `parent_run_id` 指向父 Run,trace 可串起完整调用链。

## 7. 演进

- **第一阶段**:覆盖板块中心、龙头识别、长期价值、大盘/热点、公告摘要。
- **第二阶段**:LLM 自动抽取公告/财报扩充图谱;事件驱动分析;历史回测。
- **第三阶段**:NL 问答深度集成、自动研究报告;用户自定义板块/权重/关系。
