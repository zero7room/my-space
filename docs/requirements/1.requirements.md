# 股票分析软件需求文档

## 1. 项目定位

为本人自用的股票研究辅助工具。不做交易信号，不做买卖建议，定位是"研究辅助 + 主动提醒"。

核心使用场景：

- 平时打开 Web 看板，了解市场结构、板块热度和龙头变化。
- 离开电脑时，通过飞书或电报接收关键提醒，避免漏掉重要信号。
- 关键判断由系统持续跟踪并主动推送变化。

系统的真正价值不在于给出涨跌判断，而在于把"为什么可能有影响、影响谁、证据是什么、置信度多高、风险在哪里"讲清楚。

## 2. 用户与形态

- **用户范围**：单人使用，无需账号体系、权限、订阅。
- **客户端**：Web 应用为主（浏览器访问）。
- **服务端**：独立后端服务，承担数据采集、计算、推理、提醒推送。
- **部署方式**：本地或个人云服务器即可，不考虑多租户。

## 3. 市场范围

- **A 股**：核心分析对象。覆盖板块、个股、龙头、产业链、资金流、事件。
- **美股**：作为参考输入，用于跨市场影响分析（行业映射、供应链、利率、商品）。
- **港股**：暂不作为一级分析对象，但同一公司多地上市的关联需要识别（同一 `Company` 可关联多个 `Stock`）。
- **其他外部变量**：商品价格、汇率、利率作为 `MarketVariable` 纳入影响图谱。

## 4. 多维分析能力

系统需要支持以下分析维度，每个维度都应输出可解释的结构化结论。所有结论须区分**事实关系**、**统计关系**、**推断关系**三类，并附带证据和置信度。

### 4.1 板块维度

- 全市场板块查询：行业、概念、指数、地域、事件主题。
- 每个板块需有稳定 ID、来源、更新时间、成员列表和成员变更历史。
- 板块成员、涨跌、资金流、估值、热度。
- 板块前三龙头识别与评分拆解。
- 板块之间的影响关系（上下游、替代、共振、风险偏好）。
- 概念板块需要区分强相关和弱相关，避免关键词污染。

### 4.2 龙头识别（板块前三）

龙头不能只按市值或涨幅排序，需要综合五个维度评分：

| 维度 | 权重（默认） | 关键指标 |
|------|------|------|
| 规模地位 | 25% | 市值、营收、利润、市场份额 |
| 盈利质量 | 25% | ROE、ROIC、毛利率、净利率、经营现金流 |
| 成长性 | 20% | 收入/利润增速、订单、产能、产品周期 |
| 市场关注度 | 15% | 成交额、换手率、机构持仓、分析师覆盖 |
| 产业链地位 | 15% | 核心供应商/客户、平台型、成本曲线领先 |

权重需支持按板块类型调整：

- 周期板块更重资源量、成本曲线、商品价格弹性。
- 科技板块更重成长性、研发投入、产业链位置。
- 消费板块更重品牌、渠道、现金流、利润率稳定性。
- 金融板块更重资产质量、资本充足率、利差。

输出内容：板块名称、前三龙头、综合评分、评分拆解、入选原因、主要风险、更新时间。

### 4.3 热点维度

- 当日/近期资金聚焦的板块和概念。
- 热点的持续性判断：一日游、轮动、主线。
- 热点驱动来源：政策、事件、海外联动、资金抱团。
- 热点之间的传导关系（从一个板块扩散到相邻板块）。

### 4.4 大盘维度

- 指数走势（上证、深证、创业板、科创 50、沪深 300、中证 500、中证 1000）。
- 市场宽度：涨跌家数、涨跌停统计、强弱风格切换。
- 资金面：北向、两融、ETF 申赎、主力净流入。
- 情绪指标：成交额、换手率、波动率。

### 4.5 依赖关系维度

依赖关系是系统的核心图谱能力，需覆盖：

- **龙头公司上下游产业链**：供应商、客户、竞品、替代品、原材料、渠道、核心设备、关键产品、政策事件。
- **板块影响图谱**：每条边需记录来源板块、目标板块、影响方向（正/负/非线性/不确定）、影响强度、传导时滞、证据来源、置信度、更新时间。
- **跨市场依赖**：美股公司 → A 股映射、商品 → 行业、利率 → 估值。
- **政策/事件 → 受益与承压对象**。

图谱节点类型：公司（A 股 / 港股 / 美股 / 非上市）、板块（行业 / 概念）、产品（GPU、光模块、动力电池、创新药等）、原材料（锂、铜、硅料、原油等）、客户类型（整车厂、云厂商、医院、政府等）、事件（财报、政策、制裁、价格变动）。

典型输出包括"关键风险路径"，例如：

> 美股 AI 芯片回调 → 算力链估值下降 → A 股光模块和服务器板块承压。

影响关系评分由三部分构成：

- **事实强度**：是否存在明确供应链、客户、产品或财务暴露。
- **统计强度**：历史相关性、滞后相关性、事件窗口表现。
- **逻辑强度**：产业链逻辑、成本传导、需求传导、政策传导是否成立。

### 4.6 长期价值维度

- 公司基本面：营收、利润、ROE、ROIC、现金流、毛利率。
- 成长性：收入与利润增速、订单、产能、产品周期。
- 估值历史分位：PE、PB、PS 在历史区间中的位置。
- 行业生命周期与赛道质量。
- 治理与风险：负债率、商誉、股权质押、监管风险、单一客户依赖、财务异常。

### 4.7 美股 → A 股传导

需要识别并维护以下传导路径：

- **指数情绪**：纳指、标普 500、费城半导体指数 → A 股成长股风险偏好。
- **行业映射**：英伟达、AMD、博通、台积电、特斯拉、苹果等 → A 股产业链。
- **供应链映射**：美股公司的客户、供应商、设备商、代工厂变化 → A 股相关公司。
- **商品和利率**：美元、美债利率、原油、黄金、铜 → 资源、出口、银行、成长估值。
- **政策限制**：出口管制、关税、制裁、补贴政策 → 半导体、新能源、军工等板块。

### 4.8 LLM 辅助分析

系统将接入 LLM 能力，用于：

- 公告、研报、新闻的结构化抽取（产品、客户、订单、风险）。
- 自然语言问答：用户用自然语言提问，系统结合图谱和指标作答。
- 事件解释：把财报、政策、新闻转换成对板块和个股的影响判断。
- 报告生成：自动生成板块研究、个股研究、事件分析。

LLM 输出必须附带证据来源和置信度，并归类为"推断关系"，与事实关系、统计关系明确区分。

## 5. 核心数据模型（需求视角）

系统需要支持以下核心实体（详细 schema 由设计阶段给出）：

- `Stock`：股票证券。
- `Company`：公司主体，支持一家公司多地上市。
- `Sector` / `SectorMembership`：板块及成员归属。
- `Product` / `Commodity`：产品、原材料。
- `MarketVariable`：美股指数、公司、利率、汇率、商品价格等外部变量。
- `MarketEvent`：财报、政策、新闻、订单、制裁等事件。
- `Evidence`：所有结论的证据来源（必备）。
- 关键指标：`FinancialMetric`、`MarketMetric`、`SectorMetric`、`LeaderScore`、`ImpactScore`。
- 关键关系：`belongs_to_sector`、`supplies_to`、`buys_from`、`competes_with`、`substitutes`、`depends_on`、`priced_by`、`influences`、`maps_to`、`same_theme`。

每条关系边必须包含：类型、方向、强度、置信度、证据、更新时间。

## 6. 关键用户旅程

### 6.1 查询板块和龙头

```text
用户请求 → 板块中心 → 指标层读取板块成员和公司指标
        → 龙头识别器计算前三龙头 → 证据管理器附加评分依据
        → 应用层展示龙头榜和风险提示
```

### 6.2 查看龙头上下游

```text
用户选择龙头 → 关系图谱服务 → 图谱层返回供应商/客户/竞品/产品/原材料/事件
            → 产业链分析器筛选关键路径 → 应用层展示上下游图
```

### 6.3 分析美股对 A 股影响

```text
用户输入美股事件/变量 → 事件解释器识别主体和类型
                    → 跨市场影响引擎匹配 A 股板块和公司
                    → 图谱层查询映射关系和产业链路径
                    → 指标层补充历史联动和影响强度
                    → 证据管理器附加来源和置信度
                    → 应用层输出影响路径、受益/承压对象、观察指标
```

典型自然语言问答示例（LLM 入口）：

> 用户："英伟达财报超预期对 A 股有什么影响？"
>
> 系统：识别主体（英伟达）→ 匹配 A 股板块（光模块、服务器、PCB、液冷、电力设备、半导体设备）→ 生成影响路径与置信度 → 列出可能受益、可能承压、需要观察的指标。

### 6.4 接收提醒并回看

```text
后台策略命中 → 提醒服务生成消息（含证据和上下文）
            → 推送到飞书/电报 + 写入 Web 站内通知
            → 用户在 Web 端展开证据和后续走势
```

## 7. 展示形态

Web 端需提供四类核心视图（每个节点都支持展开证据，避免黑箱）：

- **板块总览表**：所有板块、涨跌、成交额、估值、热度、龙头摘要。
- **龙头榜**：每个板块前三龙头与评分拆解、入选原因、风险。
- **产业链图**：某个龙头公司的上下游、竞品、关键依赖、原材料、客户。
- **跨市场影响图**：美股事件 → A 股板块和个股的传导路径。

辅助视图：

- 热点看板（驱动来源 + 持续性判断）。
- 大盘看板（指数 + 宽度 + 资金 + 情绪）。
- 提醒中心（历史提醒 + 上下文 + 后续走势回看）。
- 自然语言问答入口（LLM 接入后启用）。

## 8. 数据实时性策略

实时性策略分层（具体频率会随多维策略与 LLM 接入方案调整）：

- **日终数据**：财务、板块归属、龙头评分、长期价值。每日收盘后更新一次即可。
- **盘中数据**：行情、资金流、热点、情绪。分钟级或准实时。
- **事件数据**：公告、新闻、政策。到达即处理。
- **跨市场数据**：美股、商品、汇率、利率。按各自市场时段更新。

MVP 阶段以日终为主，盘中只覆盖少量关键指标。

## 9. 提醒能力

### 9.1 通知渠道

- **飞书**：通过自定义机器人推送到指定群或个人。
- **电报（Telegram）**：通过 Bot 推送到指定 Chat。
- **Web 端站内通知**：补充渠道，便于回看历史提醒。

每条提醒需要包含：触发原因、关键证据、相关板块/个股、建议关注的下一步指标、置信度、关系类型（事实/统计/推断）。

### 9.2 提醒触发来源

提醒触发支持多维策略，详细策略后续单独讨论。当前已确认的触发类别：

1. **价格 / 技术指标突破**
   - 个股或板块突破均线、压力位、支撑位、成交量异动。
   - 涨跌停、连板、龙虎榜异常。

2. **事件 / 新闻 / 公告**
   - 关注的公司或板块发布公告、财报、政策、订单、并购。
   - 监管动作、突发事件、海外政策变化。

3. **美股联动信号**
   - 美股龙头（英伟达、特斯拉、苹果等）异动并通过映射关系传导到 A 股板块。
   - 美债利率、美元、商品价格触发关联板块预警。

4. **分析结论变化**
   - 板块前三龙头排名变化。
   - 影响关系置信度或强度发生显著变化。
   - 长期价值评分跨越关键阈值。
   - LLM 结论或事件解释发生方向性变化。

5. **多维策略组合**（后续展开）
   - 多个维度同时满足条件时触发，例如"板块走强 + 资金净流入 + 美股相关板块上涨"。
   - 策略可配置、可启用、可停用，支持自定义阈值。

### 9.3 提醒控制

- 静默时段：非交易时间默认降级，重大事件除外。
- 去重与合并：同一标的短时间内多条提醒应合并。
- 优先级：高 / 中 / 低三级，对应不同推送频率。
- 历史回看：每条提醒可在 Web 端查看上下文和后续走势。
- 关系过期降权：当证据或更新时间超过阈值时，相关提醒自动降级。

## 10. 数据质量与风险控制

系统需要避免把噪声包装成结论，关键控制点：

- 区分事实、统计、推断三类关系。
- 每个重要结论保存证据。
- 每条关系有更新时间，过期关系需降权。
- 对低置信度结论做明显标记。
- 不把短期涨跌直接解释为因果。
- 不把概念板块中的弱相关公司误判为核心龙头。
- 对财务异常、交易异常、政策风险做单独提示。

默认风险提示文案：

- 相关不等于因果。
- 历史关系可能失效。
- 龙头排名会随财报、价格、资金偏好变化。
- 板块概念可能被市场短期炒作扭曲。
- 海外影响 A 股时，汇率、政策、交易时段、流动性都会改变传导结果。

## 11. 非功能需求

- **可解释性**：所有结论必须能展开证据链。
- **置信度透明**：事实、统计、推断三类关系明确区分。
- **数据可追溯**：每个数据点保留来源、采集时间、可信度。
- **可演进**：架构支持从日终走向盘中、从规则走向 LLM、从单维走向多维组合策略。
- **低运维成本**：单人使用前提下，部署、备份、升级要轻量。

## 12. MVP 范围

第一阶段聚焦"看得清 + 提醒到"。

### 12.1 MVP 必做

- 板块总览、板块成员、板块前三龙头与评分拆解。
- 个股长期价值评分（基本面 + 估值分位）。
- 大盘与热点看板。
- 少量手工维护的产业链关系与美股映射。
- 飞书 / 电报机器人接入，支持基础提醒（价格突破、公告事件、龙头变化）。
- LLM 辅助：公告摘要 + 自然语言问答（轻量集成）。
- 证据管理：每条结论可展开来源和更新时间。

### 12.2 MVP 首批覆盖（美股 → A 股映射）

优先维护以下高价值传导路径：

- **英伟达** → AI 算力、光模块、服务器、PCB、液冷、电力设备。
- **特斯拉** → 锂电池、汽车零部件、智能驾驶。
- **苹果** → 消费电子、面板、精密制造。
- **费城半导体指数** → 半导体设备、材料、设计、封测。
- **美债利率** → 高估值成长股、黄金、银行。

### 12.3 MVP 暂不做

- 自动交易、买卖建议、组合回测。
- 实时 tick / Level-2 行情。
- 多用户、订阅、付费体系。
- 全量复杂策略引擎（多维策略后续单独设计）。
- 全量实时图数据库（先用关系型 + JSON 模拟）。
- 投资组合 / 持仓管理 / 仓位推荐（与"研究辅助"定位冲突，明确不做）。
- 无证据的黑箱结论。

## 13. 后续演进

**第二阶段**：

- 自动抽取公告/财报中的客户、供应商、产品、产能、订单。
- 建立更完整的板块影响图谱。
- 支持事件驱动分析。
- 加入历史回测，验证影响关系是否有效。

**第三阶段**：

- 引入图数据库。
- 支持实时预警。
- 支持自然语言问答深度集成。
- 支持自动生成研究报告。
- 支持用户自定义板块、权重、影响关系。

## 14. 关键决议（2026-05-08）

以下事项已敲定，作为本项目阶段一（MVP）的技术选型与设计基线。每条决议同时标注其在 `docs/design/architecture.md` 的影响章节。

### 14.1 服务端技术栈

- **决议**：Python · FastAPI（API 层）· APScheduler（轻量调度）· Celery（重任务/事件驱动）。
- **理由**：A 股数据生态（akshare/Tushare）、LLM 客户端、pandas 计算栈在 Python 上最成熟。
- **影响**：架构 §3.3 Runtime、§3.5 Orchestration。

### 14.2 存储方案

- **决议**：PostgreSQL（实体/指标/关系/提醒）+ JSONB 字段（证据列表、Skill 产物、策略配置）+ 本地文件系统（原始件、Run 留痕、看板缓存）。MVP 不上 Redis、不上 pgvector。
- **理由**：单人使用、低运维、单进程能跑通。
- **演进**：第二阶段评估 Redis 缓存；文本入向量库放第三阶段。
- **影响**：架构 §3.1 Data Layer、§6 存储目录。

### 14.3 LLM 接入

- **决议**：多云提供商抽象 + 内部 `LLMGateway` 模块。常规抽取/摘要走低价模型；深度推理与报告走高端模型；统一开 prompt cache 与 batch；Run 级 token / 成本 / 调用上限。
- **路由策略变量**：`task_kind`（extract / summarize / qa / report）× `latency_budget` × `cost_budget`。
- **影响**：架构 §3.3 新增 `LLMGateway`；§8 预算与限速规则落到 Gateway。

### 14.4 数据源选型

- **A 股**：akshare 主源（行情/资金/板块/龙虎榜/公告）+ Tushare 补（部分财务字段，按需开启）。
- **美股 / 外部变量**：yfinance（股价/财报）+ FRED（美债利率、通胀指标）+ akshare（商品价格、汇率作为补充）。
- **影响**：架构 §3.1 Collector 列表落实。

### 14.5 板块来源策略

- **决议**：多源并存 + canonical 映射。
  - `provider_sector`：保留来源标签（东财/同花顺/交易所/自建），作为溯源。
  - `canonical_sector`：唯一对外身份，所有 Skill 与页面只读 canonical。
  - `sector_mapping`：`provider_sector → canonical_sector` 多对多映射，带 `relevance`、`as_of`。
- **概念污染防护**：弱相关概念板块的成员需通过 `relevance × confidence ≥ 阈值` 才能进入龙头候选。
- **影响**：架构 §3.2 `Sector` 拆为三表；新增映射维护工作流。

### 14.6 Evidence Schema

- **决议**：全字段 schema。基础字段：

  ```
  id            UUID
  type          enum(announcement, filing, news, research, stat, llm, manual)
  source        text       -- 来源系统/网站/作者
  url_or_path   text       -- 公网 URL 或本地相对路径
  title         text
  excerpt       text       -- 200 字摘录，便于前端展示
  observed_at   timestamptz
  hash          text       -- 内容指纹，去重
  lang          text       -- zh / en
  extra         jsonb      -- 类型相关子字段
  ```

  按 `type` 在 `extra` 中携带子字段：
  - `stat`：`metric_id`、`window_start`、`window_end`、`sample_size`。
  - `llm`：`model`、`prompt_hash`、`temperature`、`output_kind`（用于复现与隔离）。

- **强约束**：缺 evidence 不出库、缺 `relation_class` 不出库、缺 `observed_at` 不出库。
- **影响**：架构 §3.2 Evidence 章节落实；§8 LLM 隔离规则可机械校验。

### 14.7 抽取分工

- **规则抽取**：所有结构化数字（行情、资金、财报数字、龙虎榜、指数、利率、汇率、商品价）。
- **LLM 抽取**：公告 / 研报 / 新闻文本中的"主体、产品、订单、客户、风险、预期变化"等结构化字段；输出统一落 `inferred` evidence。
- **手工录入**：MVP 阶段 §12.2 五条高价值映射的产业链关键边由人工维护并打 `fact` class，更新走"映射工作流"（增 / 改 / 失效降权）。
- **影响**：架构 §3.4 事件解释器实现细则；§3.5 Scheduler 加文本到达触发。

### 14.8 龙头评分校准

- **MVP**：四套板块类型权重模板（周期 / 科技 / 消费 / 金融），按板块标签加载。每条龙头结论必须输出"评分拆解快照"（五维原始指标 + 加权后得分）。
- **演进**：第二阶段加事件窗口回测——龙头变动 vs 后 30 / 60 / 90 日相对板块超额收益——验证默认权重；不达标的板块类型重新拟合。
- **影响**：架构 §3.4 Leader Identifier 输入新增 `sector_profile`；§9 演进路线写入回测计划。

### 14.9 策略 DSL

- **决议**：YAML / JSON 表达式。变量空间：`metric.<id>` / `relation.<edge_id>` / `event.<type>` / `sector.<field>` / `symbol.<field>`。运算符：`and / or / not / >= / <= / > / < / within(window) / changed(field, period)`。
- **触发源**：调度 tick + 事件到达 + 指标变更（CDC 风格）。
- **示例**：

  ```yaml
  id: cpo_strong_with_us_peer
  enabled: true
  priority: high
  when:
    all:
      - sector.pct_change('BK_CPO') > 0.03
      - sector.net_inflow('BK_CPO') > 100000000
      - within('2h'):
          event.us_peer_move(symbol='NVDA') > 0.02
  notify:
    summary: "光模块走强 + 北向流入 + 英伟达异动"
    refs:
      - sector: 'BK_CPO'
      - symbols: ['300308', '300394']
  ```

- **影响**：架构 §3.5 新增 `RuleParser` + `ExpressionEvaluator` + `VariableResolver`。

### 14.10 提醒疲劳管理

- **决议**：三重闸 + 每日上限。
  1. **去重**：`(subject, alert_type)` 30 分钟窗口内合并为最新一条。
  2. **合并**：滑动 1 小时同主体 ≥ N 条同向提醒，自动合并为"摘要包"发送。
  3. **静默**：非交易时段降级（高优先级仍发，中/低延后到次日开盘前一小时）。
  4. **每日上限**：高 ≤ 20、中 ≤ 10、低 ≤ 5；超出走"日报"汇总。
- **影响**：架构 §3.5 Notifier 加合并 / 优先级 / 上限 / 静默逻辑。

## 15. 客户端规划

### 15.1 框架与渲染

- **决议**：Next.js 16（App Router）+ React 19，默认 React Server Components，按需客户端组件。
- **服务端策略**：首屏（板块总览、龙头榜、大盘看板）走 RSC 服务端预取；交互组件（筛选、图谱、对话框）走客户端组件。
- **与后端关系**：FastAPI 提供 REST API；Next 仅承担页面与 BFF（缓存、聚合、轻鉴权、SSE 转发）。

### 15.2 UI 与样式

- **决议**：shadcn/ui 复制式组件 + Tailwind v4。
- **主题**：浅色为主，预留暗色 token；行情色按"红涨绿跌"配置变量，可由用户切换。

### 15.3 可视化

- **表格 / 趋势 / 排行**：ECharts。
- **产业链图 / 跨市场影响图**：Cytoscape.js。节点类型按 §4.5 图谱节点类型着色（公司 / 板块 / 产品 / 原材料 / 客户 / 事件），边宽度对应 `strength × confidence`，过期边自动降饱和度。
- **大数据量优化**：板块/股票总览使用 `@tanstack/react-virtual` 虚拟滚动。

### 15.4 前后端契约

- **决议**：REST + OpenAPI 自动生成 TypeScript 客户端（`openapi-typescript-codegen`）。
- **API 版本**：`/api/v1/*`。资源化：`/api/v1/sectors`、`/api/v1/sectors/{id}/leaders`、`/api/v1/symbols/{code}`、`/api/v1/runs/{run_id}`、`/api/v1/alerts`。
- **Artifact 渲染**：前端按 §5 Artifact schema 渲染 `summary / highlights / charts / data`，证据点击展开 `raw_pointer`。

### 15.5 数据层

- **服务端状态**：TanStack Query（缓存、去重、后台刷新、分页、Suspense 集成）。
- **UI 状态**：Zustand（跨页面轻量全局：选中板块、筛选条件、主题）。
- **错误与加载**：Suspense + ErrorBoundary 模式；接口失败统一引导到证据缺失提示。

### 15.6 工程化

- **包管理**：pnpm。
- **代码质量**：ESLint flat config + Prettier + `tsc --noEmit` + Vitest（组件单测）+ Playwright（E2E 关键路径：板块查询、龙头展开、跨市场分析、提醒中心）。
- **部署**：MVP 本地 Node 进程；生产同机部署，Caddy 反代 `/api/*` → FastAPI、其它 → Next.js。
